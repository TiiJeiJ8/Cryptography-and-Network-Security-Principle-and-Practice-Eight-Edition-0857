# 第22章 云计算 — 章末学习目标自检

---

## 1. 能否说明云计算的 NIST 定义及广泛网络接入、快速可伸缩性、计量、自助和资源池化五个特征？

**NIST 定义**：云计算是通过网络对共享的可配置计算资源池进行无处不在、方便、按需的访问，并以很少的管理开销或服务提供者交互实现快速提供和释放的模型。资源池包括网络、服务器、存储、应用和服务。

| 特征 | 含义 |
| --- | --- |
| **广泛的网络接入** | 通过网络和标准机制提供功能，手机、笔记本、PDA 等各类客户端均可访问 |
| **快速可伸缩性** | 按需求快速扩展或释放资源，资源规模对用户近似无限 |
| **计量服务** | 按存储、处理、带宽或活跃账户自动计量、监视、控制和报告使用情况 |
| **按需自助服务** | 消费者可单方面获取服务器时间、网络存储等资源，无须逐次人工交互 |
| **资源池化** | 提供商汇集物理和虚拟资源，以多租户方式动态分配；消费者只指定较高层次位置，不能控制具体设备 |

五特征共同形成云的弹性和经济性：资源不是企业永久拥有的 IT 组成，而是按需取得、使用和释放的服务。

## 2. 能否比较 SaaS、PaaS 和 IaaS 的用户能力、责任边界和典型用途？

三模型逐层嵌套：SaaS 建立在 PaaS 之上，PaaS 和 SaaS 建立在 IaaS 之上。

| 模型 | 用户获得的能力 | 用户控制 | 提供商负责 | 典型例子 |
| --- | --- | --- | --- | --- |
| **SaaS（软件即服务）** | 直接使用云中运行的应用软件 | 应用使用和部分数据配置 | 基础设施、平台及应用部署、维护、升级、补丁 | Gmail、Microsoft 365、Salesforce |
| **PaaS（平台即服务）** | 在云平台上开发、测试、部署和管理应用 | 自己部署的应用及数据 | 基础设施、运行环境、数据库、中间件、开发工具 | Google App Engine、Heroku |
| **IaaS（基础设施即服务）** | 使用虚拟机、存储、网络部署任意软件 | 操作系统、应用程序及部分网络组件（主机防火墙） | 物理服务器、网络、存储、托管设施 | Amazon EC2、Azure VM |

核心差异是**责任边界**：从 SaaS 到 IaaS，消费者控制力逐渐增加，同时承担更多配置和安全责任。

## 3. 能否定义公有云、私有云、社区云和混合云，并比较它们的成本、安全性、扩展性和管理方式？

| 模型 | 所有权和使用方式 | 优势 | 限制或风险 |
| --- | --- | --- | --- |
| **公有云** | 面向公众，提供商拥有运营，多租户共享 | 成本低、按使用付费、易扩展、管理开销小 | 服务等级和数据恢复保证可能较低；租户隔离取决于提供商 |
| **私有云** | 企业内部实现或第三方专用资源托管 | 对数据位置、安全控制和资源共享控制最强，安全性最高 | 成本较高，扩展性受企业资源限制 |
| **社区云** | 有共同需求的多个机构共享（如卫生保健机构） | 满足法规和数据交换需求的同时分摊成本 | 参与者较少，规模介于公有与私有之间 |
| **混合云** | 两个或多个独立云通过标准化或专有技术连接 | 敏感信息留私有区域，非敏感信息利用公有云弹性 | 需保证跨云数据与应用可移植性及安全链路 |

属性比较：公有云扩展性最高、成本最低；私有云成本最高但安全性、性能和可靠性最好；混合云兼顾扩展性、安全性和性能。

## 4. 能否说明 NIST 云计算参考架构的用途、五个主要角色及三类网络关注点？

参考架构是讨论云服务"是什么"的通用高层概念模型，不是具体实现架构，用于理解、分类和比较云服务，支持安全性、互操作性、可移植性分析。

**五个主要角色**：

| 角色 | 职责 |
| --- | --- |
| **云服务消费者（CSC）** | 与提供商保持商业关系并使用云服务的个人或企业 |
| **云服务提供商（CSP）** | 提供一个或多个云服务，管理存储、处理设施和云接口 |
| **云审计者** | 独立评估云服务操作、性能、安全性和隐私控制 |
| **云经销商/代理商** | 在 CSP 与用户之间管理、组合或转售服务，提供身份管理、性能报告等增值服务 |
| **云承载商** | 提供 CSC 与 CSP 之间的连接和传输，可按 SLA 提供专用安全连接 |

云代理商三类服务：服务中介（增加身份管理、报告、安全功能）、服务聚合（组合多个云服务）、服务套利（灵活选择不同代理机构服务）。

**三类网络关注点**：CSP 数据中心网络（虚拟机部署、迁移、负载均衡、可用性）；企业网络（LAN、服务器、工作站、移动设备的性能安全管理）；云承载商网络（在 SLA 和安全保证下建立虚拟网络）。

## 5. 能否用责任划分和 STRIDE 模型分析数据泄露、IAM、API、APT、数据丢失和共享技术等云安全威胁？

**责任划分**：云计算没有消除传统 IT 安全问题，还因多租户、资源共享、动态分配和控制权转移产生特殊风险。云用户负责应用级安全，CSP 负责物理设施和部分软件安全，中间软件层由双方共同保障。采用云服务前须调查 CSP 安全能力、合同、SLA、数据位置、可审计性和退出机制。

**STRIDE 威胁模型**（每类威胁对应一种安全控制）：

| 类别 | 含义 | 对应控制 |
| --- | --- | --- |
| **S** 身份欺骗 | 使用他人身份凭证访问系统 | 认证 |
| **T** 篡改数据 | 未授权修改存储或传输中的数据 | 完整性 |
| **R** 抵赖 | 用户否认操作而系统无法证明 | 不可抵赖 |
| **I** 信息泄露 | 信息被不应接触者获取 | 保密性 |
| **D** 拒绝服务 | 使有效用户无法获得服务 | 可用性 |
| **E** 提升权限 | 非特权用户获得破坏系统的权限 | 授权 |

**主要云威胁与对策**：

| 威胁 | 风险 | 对策 |
| --- | --- | --- |
| **数据泄露** | 敏感数据被查看、窃取、篡改；密钥丢失放大后果 | 访问控制；保护静止/传输/使用中数据；客户端加密并自持密钥 |
| **弱身份、凭证和访问管理** | 认证、授权或用户配置不足 | 建立可信 IAM、身份提供和可审计访问控制 |
| **不安全的 API** | API 绕过认证、授权、加密或监控策略 | 强认证、访问控制、加密传输，理解依赖链 |
| **账号劫持** | 窃取凭证后破坏保密性、完整性、可用性 | 禁止共享凭证，强双因素认证，主动监测 |
| **恶意内部人员** | CSP 高权限角色滥用信任 | 供应链评估、合同约束、透明管理流程 |
| **APT** | 长期隐蔽驻留窃取高价值信息 | 威胁情报缩短检测和补救时间 |
| **数据丢失** | 数据或备份被意外或恶意删除 | 定期备份、地理冗余 |
| **共享技术漏洞** | 多租户共享 CPU/GPU，隔离不足导致跨租户风险 | 安全配置、变更监控、及时修补、漏洞扫描审计 |

APT 典型阶段：背景研究→初始社会工程→建立立足点→维持持久性→企业侦察→横向迁移→提升特权→收集加密资料→提取数据→长期驻留。

## 6. 能否列出 SecaaS 的十类服务，并说明 DLP、Web 安全、入侵管理、SIEM、加密和灾难恢复的作用？

**安全即服务（SecaaS）** 把一组安全责任交给服务提供者，通常是 CSP 的 SaaS 产品组成部分。云安全联盟列出十类：

| 服务 | 作用 |
| --- | --- |
| **身份和访问管理（IAM）** | 管理身份验证、授权和访问权限 |
| **数据丢失防护（DLP）** | 监视、保护和验证静止、传输及使用中的数据 |
| **Web 安全** | 通过代理、设备或流量重定向实时阻止恶意软件，提供策略执行、流量控制 |
| **电子邮件安全** | 控制入站出站邮件，防御钓鱼和恶意附件，统一签名加密 |
| **安全评估** | 第三方审计云服务，CSP 提供评估工具和接入点 |
| **入侵管理** | 提供 IDS、IPS 及入侵响应；IPS 在 IDS 检测基础上增加阻断 |
| **安全信息和事件管理（SIEM）** | 聚合、关联和分析虚拟及真实网络、应用、系统的日志事件，产生实时报告告警 |
| **加密** | 保护云数据、邮件流量、管理和身份信息，涉及密钥管理和 VPN |
| **业务连续性和灾难恢复** | 通过冗余、故障转移、地理分布数据中心和备份保持服务弹性 |
| **网络安全** | 边界防火墙、服务器防火墙和 DoS 防护等底层资源保护 |

SecaaS 价值在于利用提供者的规模和专业能力，但企业仍需确认数据控制、密钥管理、审计、SLA 和责任边界。

## 7. 能否解释 Keystone 的身份、令牌、服务目录和策略服务，以及它与 Nova、Glance、Swift 的协作？

OpenStack 是支持多租户 IaaS 的开源云操作系统，**Keystone** 提供共享的身份和访问控制服务，包含四类服务：

| 服务 | 作用 |
| --- | --- |
| **身份** | 保存用户身份信息，定义项目中的角色和权限，是 RBAC 基础；支持用户名/口令、LDAP 和外部认证 |
| **令牌** | 用户认证后获得令牌，其他 OpenStack 服务在操作期间用令牌向 Keystone 查询访问权限 |
| **服务目录** | 注册服务端点；客户端按 Keystone 返回的目录确定要调用的端点 |
| **策略** | 在各服务策略文件中定义资源访问级别，管理员可控制 API、卷容量或实例启动等权限 |

**与其他模块协作**：

| 模块 | 职责 |
| --- | --- |
| **Nova** | 管理计算实例生命周期，按需生成、调度和报废虚拟机 |
| **Glance** | 通过 API 对虚拟机磁盘映像进行发现、注册和检索 |
| **Swift** | 冗余、可扩展的分布式对象存储，保存映像、备份等静态数据 |

**启动 VM 流程**：客户端请求启动 → Nova 与 Keystone 发现服务并检查凭证 → Nova 调度 VM，必要时向 Glance 请求映像 → Glance 返回映像位置 → Nova 向 Swift 请求取得映像 → 启动 VM。Keystone 在各服务间持续提供认证、令牌和端点发现。
