# 第21章 网络端点安全 — 章末学习目标自检

---

## 1. 能否说明防火墙在深度防御中的位置、三个设计目标、四项主要作用及能力边界？

**深度防御中的位置**：防火墙部署在本地网络与因特网之间形成受控边界，也可部署在企业内部隔离不同网段。它是主机安全服务的补充——即使某一层防护失效，其他层仍可限制攻击扩散。

**三个设计目标**：
1. 内外之间全部流量必须经过防火墙，不存在绕行路径；
2. 只有本地安全策略授权的流量才允许通过；
3. 防火墙本身必须抗渗透，运行在安全可信的系统上。

**四项主要作用**：

| 作用 | 说明 |
| --- | --- |
| 集中阻断 | 统一阻止点，拦截未授权访问、脆弱服务、IP 欺骗和路由攻击 |
| 监控与审计 | 为安全事件记录、审计和告警提供集中位置 |
| 附加网络功能 | 承载网络地址转换（NAT）和网络使用记录 |
| VPN 平台 | 作为虚拟专用网的实现平台 |

**能力边界**（防火墙不是完整端点安全方案）：不能防御绕过防火墙的通信路径；不能完全防御内部人员威胁；不能阻止绕过内部隔离边界的无线通信；不能避免移动设备在外部感染后接入内网传播恶意软件。因此必须与主机防护、IDS、恶意软件防御和事件响应配合。

## 2. 能否列出防火墙的四种访问控制功能，并比较四类防火墙的工作方式、优点和局限？

**四种访问控制功能**：

| 功能 | 控制内容 |
| --- | --- |
| **服务控制** | 决定允许哪些入站/出站服务，依据地址、协议、端口或代理解释结果过滤 |
| **方向控制** | 决定服务请求允许从哪个方向发起 |
| **用户控制** | 根据用户身份决定访问权限（外部用户需安全认证） |
| **行为控制** | 限定服务使用方式，如过滤垃圾邮件、限制外部只能访问部分信息 |

**四类防火墙**：

| 类型 | 工作方式 | 优点 | 局限 |
| --- | --- | --- | --- |
| **数据包过滤** | 独立检查每个 IP 包，按源/目的 IP、端口、协议、接口字段决定转发或丢弃 | 简单、快速、对用户透明 | 不检查上层数据，日志和认证能力有限，易受协议欺骗和错误配置影响 |
| **状态检查** | 在包过滤基础上维护当前连接目录，只放行符合合法连接状态的流量 | 能限制伪装成响应的入站流量，可跟踪 TCP 序号 | 仍需正确维护状态和策略 |
| **应用层网关** | 作为应用代理终止原连接，再代表用户建立新连接，检查并转发应用数据 | 可限制应用具体功能，日志审计能力强 | 每连接额外处理，每种应用需专用代理 |
| **电路层网关** | 建立内外两个 TCP 连接，获准后中继 TCP 段，通常不检查内容 | 适合信任内部用户，出站开销低 | 对应用内容控制弱 |

**默认策略**：默认丢弃（白名单，未明确允许全部丢弃）更保守安全；默认转发（黑名单）方便但需持续封堵新威胁。规则按顺序匹配，规则顺序本身就是策略。

**典型包过滤攻击及对策**：IP 地址欺骗（外部接口丢弃源地址属于内网的包）；源路由攻击（丢弃带源路由选项的包）；极小数据段攻击（要求首段包含最小 TCP 头部并关联丢弃其余分段）。

## 3. 能否解释外部防火墙、DMZ 和内部防火墙的相对位置及分层配置的三项优点？

**典型配置**：外部防火墙位于企业网边缘提供基本访问控制；外部防火墙与内部防火墙之间形成 **DMZ（非军事区）**，放置必须接受外部连接但仍需保护的 Web、邮件、DNS 服务器；内部防火墙位于 DMZ 与核心企业网之间，实施更严格策略。

**分层配置的三项优点**：
1. 内部防火墙采用比外部防火墙更严格的过滤规则，重点保护内部服务器和工作站；
2. 内部防火墙对 DMZ 提供**双向隔离**：既阻止被攻陷的 DMZ 主机攻击内网，也限制内网攻击 DMZ；
3. 多个内部防火墙可进一步分隔服务器、数据库和工作站网段，限制内部攻击和横向传播。

核心思想：公开服务与重要内部资源分离，即使 DMZ 主机失陷，攻击者仍须突破内部防火墙才能进入核心网络。

## 4. 能否定义入侵、入侵检测和 IDS，说明 IDS 的三个逻辑组件，并比较误用检测与异常检测？

- **入侵**：违反安全策略，试图损害系统保密性、完整性或可用性的行为；攻击者可来自外部，也可是滥用权限的授权用户。
- **入侵检测**：收集并分析系统或网络事件以发现入侵迹象的过程。
- **IDS**：从计算机或网络不同区域收集分析信息、识别未授权访问并提供实时或近实时警告的软硬件系统，是认证、访问控制和防火墙之后的另一道防线。

**三个逻辑组件**：

| 组件 | 职责 |
| --- | --- |
| **传感器** | 从网络数据包、日志文件、系统调用轨迹采集可能含入侵证据的数据 |
| **分析器** | 判断是否发生入侵，输出证据并给出响应建议 |
| **用户接口** | 展示检测结果并允许用户控制系统（控制台） |

**两种检测方法**：

| 方法 | 判定依据 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **误用检测（签名检测）** | 事件与已知攻击规则/签名匹配 | 对已知攻击准确率高、误报少 | 无法检测无签名的新攻击（零日） |
| **异常检测** | 建立正常行为模型，寻找明显偏离的活动 | 可发现未知攻击 | 正常与攻击行为分布重叠，需权衡误报与漏报 |

判定范围越宽，发现越多但误报增加；越严格，误报减少但漏报增加。

## 5. 能否比较 HIDS 与 NIDS 的数据来源和检测能力，列出 NIDS 的三类签名及四类部署位置？

| 类型 | 数据来源 | 检测能力 |
| --- | --- | --- |
| **HIDS（基于主机）** | 主机活动、数据文件、系统进程、系统调用、日志 | 易确定攻击进程和用户账号；能检测 NIDS/防火墙不易发现的内部入侵；结合阈值检测和基于配置文件的检测 |
| **NIDS（基于网络）** | 网卡设混杂模式捕获所在网段流量 | 看见跨主机流量；单传感器只观察本地网段，多传感器由中央管理器汇总 |

**NIDS 三类签名**：

| 签名 | 检查对象 | 示例 |
| --- | --- | --- |
| **字符串签名** | 净荷中的攻击文本串（可组合多串降误报） | UNIX/Web 服务器攻击的特定字符串组合 |
| **端口签名** | 常遭攻击或不应开放的端口 | Telnet 23、FTP 21/20、SUNRPC 111、IMAP 143 |
| **头部签名** | 头部中危险或逻辑矛盾的标志组合 | 同时置 TCP SYN 和 FIN；NetBIOS 异常指针 |

**四类部署位置**：
1. 主防火墙外：测量来自因特网的总体威胁水平；
2. DMZ 内：监控针对公开服务的渗透；
3. 内部防火墙后骨干网处：监控内部服务器和数据库网段；
4. 内部防火墙后用户局域网处：监控工作站网段并发现内部攻击。

## 6. 能否区分病毒、蠕虫、特洛伊木马、间谍软件、Rootkit、后门、移动代码和僵尸？

| 类型 | 核心特征 |
| --- | --- |
| **病毒** | 自我复制并**附着于宿主程序**，用户不知情时感染系统，可破坏数据或借邮件传播 |
| **蠕虫** | **独立程序**，利用网络自行传播，不需人工干预，不集成到已有代码，通常攻击已知漏洞 |
| **特洛伊木马** | 表面有用、内部隐藏恶意功能，借调用者合法授权逃避安全机制 |
| **间谍软件** | 秘密安装，在个人或企业不知情时收集信息 |
| **Rootkit** | 取得根级访问后用于隐藏活动、长期维持隐蔽高权限的一组工具 |
| **后门** | 绕过正常安全控制、秘密进入系统的非法途径 |
| **移动代码** | 可不加修改发布到异构平台并以相同语义运行的脚本、宏或可移植指令 |
| **僵尸（Bot）** | 安装在受控系统上接受指令发动攻击的程序，大量协同构成僵尸网络 |

病毒与蠕虫的关键区别：病毒依附宿主程序，蠕虫独立并通过网络自动传播。

## 7. 能否从两个时间尺度说明恶意软件防御，并概述网络流量分析、净荷分析、端点行为分析、事件管理和取证？

**两个时间尺度**：实时/近实时防御监控并阻止正在发生的攻击；攻击后防御分析事件报告和流量模式，据经验改进控制。

**五个防御要素**：

| 要素 | 时间尺度 | 内容 |
| --- | --- | --- |
| **网络流量分析** | 实时 | 在边界、内部设备或端点附近监控流量，以签名或异常发现流量激增、异常 DNS |
| **净荷分析** | 实时 | 检查数据包应用数据，寻找已知恶意净荷；可在沙箱中隔离观察可疑净荷 |
| **端点行为分析** | 实时 | 杀毒软件、应用白名单、应用容器，识别恶意行为并隔离应用和文件 |
| **事件管理** | 攻击后 | 数据收集、聚合、规范化、关联、警报和报告/合规，更新签名和异常配置 |
| **取证** | 攻击后 | 在保持数据完整性和严格监管链前提下识别、收集、检查和分析证据 |

事件管理中：聚合整合多来源资源；规范化转为公共格式；关联在时间窗口内连接多个事件发现单事件无法揭示的异常。数字取证回答发生了什么、由谁造成、何时、如何、事件顺序、影响和原因。

## 8. 能否说明 DDoS 消耗的两类资源、SYN 洪泛过程、直接式与反射式攻击、僵尸网络构建及三道防线？

**DoS** 试图阻止合法用户正常使用服务；来自大量分布式受控主机时为 **DDoS**。

**消耗的两类资源**：

| 目标资源 | 典型方式 | 结果 |
| --- | --- | --- |
| 目标系统内部资源 | SYN 洪泛、耗尽进程表或磁盘 | 服务器状态结构耗尽，无法处理合法请求 |
| 局域网数据传输能力 | 大量主机或反射器发送响应流量 | 链路带宽被占满，合法流量无法通过 |

**SYN 洪泛过程**：受控主机发送伪造源 IP 的 TCP SYN → 服务器回 SYN/ACK 并为半开连接保留状态 → 伪造地址永不完成握手 → 半开连接耗尽服务器资源。

**直接式 vs 反射式**：

| 类型 | 路径 | 特点 |
| --- | --- | --- |
| **直接式** | 攻击者→主僵尸→从僵尸→受害者 | 两层结构使攻击源难追踪 |
| **反射式** | 僵尸伪造受害者源地址→未感染反射器→受害者 | 反射器响应汇聚受害者，主机更多、流量更大、更难过滤追踪 |

**僵尸网络构建三要素**：僵尸软件；大量有普遍漏洞未修补的系统；发现脆弱主机的扫描策略（随机扫描、攻击列表扫描、局部解剖扫描、局域子网扫描）。

**三道防线**：
1. **攻击预防和抢占（攻击前）**：资源消耗策略、后备资源、改进协议；
2. **攻击检测和过滤（攻击中）**：尽早识别可疑模式并过滤攻击包；
3. **攻击源追踪和识别（攻击中及后）**：确定攻击来源，为缓解和预防提供依据。

DDoS 方式多样且不断变化，没有单一机制能彻底解决，三道防线需持续更新协同。
