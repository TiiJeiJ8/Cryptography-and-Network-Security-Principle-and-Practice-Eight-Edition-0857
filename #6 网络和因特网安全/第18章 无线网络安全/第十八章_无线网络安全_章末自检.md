# 第18章 无线网络安全 — 章末学习目标自检

---

## 1. 能否从信道、移动性、资源和易接近性解释无线网络为何比有线网络更易受攻击？

| 因素 | 安全影响 |
| --- | --- |
| **信道** | 无线是广播通信，信号穿透物理边界，任何人无需物理接入即可窃听、干扰和主动利用，而有线网络需物理接入线路 |
| **移动性** | 设备可离开受控区域，带来丢失、窃取和跨网络自动连接风险；漫游过程也可能被利用 |
| **资源** | 智能手机、传感器等资源受限（功耗、算力、存储），难以运行复杂安全机制，易受 DoS 和恶意软件影响 |
| **易接近性** | 无人照管或部署在敌占区域的设备更容易遭受物理攻击、拆解和固件篡改 |

攻击面来自三部分：无线客户端/端点、无线接入点（AP）和广播无线介质。

## 2. 能否列出意外关联、恶意关联、MAC 欺骗、中间人、DoS 和网络注入等威胁，并为其匹配安全措施？

| 威胁 | 含义 | 匹配措施 |
| --- | --- | --- |
| **意外关联** | 覆盖范围重叠，用户误连相邻网络导致资源暴露 | 关闭自动关联、加密全部传输、认证 |
| **恶意关联** | 攻击者伪装合法 AP（Evil Twin），窃取口令后再经合法 AP 进入有线网络 | 802.1X 基于端口的访问控制、双向认证 |
| **自组网络/非传统网络** | Ad Hoc、蓝牙等缺乏中央控制，易受窃听欺骗 | 禁用非授权 Ad Hoc、链路加密 |
| **身份盗窃（MAC 欺骗）** | 监听并复制合法设备 MAC 地址 | 不能仅靠 MAC 过滤，需密码学认证和密钥机制 |
| **中间人攻击** | 使用户和 AP 误以为彼此直连，实际都连到攻击设备 | 相互认证、证书、802.11i 四次握手 |
| **DoS** | 不断发送请求耗尽 AP 或端口资源 | 现场调查、频率规划、信号控制、入侵检测 |
| **网络注入** | 向暴露的 AP 注入路由、管理或伪造重置消息 | 认证管理帧、802.1X 端口控制 |

总体措施分三层：无线传输（缩小覆盖、定向天线、加密、认证）；接入点（802.1X 端口控制防恶意 AP）；网络及端点（加密路由流量、防病毒、防火墙、IDS/IPS、关闭标识广播、改默认口令）。MAC 地址以明文出现在帧头且可被软件修改，因此 MAC 过滤只能作为辅助策略。

## 3. 能否区分移动设备的设备安全、数据流安全和屏障安全，并说明 BYOD、云同步和不可信应用带来的风险？

| 类别 | 主要控制 |
| --- | --- |
| **设备安全** | 自动锁定、PIN/口令、禁止自动填充；远程清除和禁用；及时更新系统与应用；反病毒；敏感数据不本地存储或加密存储；限制第三方应用、白名单或沙箱；限制云同步；数字签名和公钥证书验证应用；限制摄像头、位置服务和越狱/Root 设备 |
| **数据流安全** | 使用 SSL、IPsec/VPN 加密全部移动设备—企业流量；设备认证与用户认证的**双层认证** |
| **屏障安全** | 专用防火墙、入侵检测和入侵阻止系统，限制移动设备可访问的数据和应用 |

三类典型风险：
- **BYOD（使用不可信移动设备）**：个人设备可能未加密，或安全 OS 已被越狱/Root 绕过，企业数据与个人数据混存；
- **云同步（与其他系统交互）**：自动同步联系人、照片、文档和云存储，可能把企业数据复制到企业控制之外的不安全位置；
- **不可信应用**：第三方应用可能包含恶意软件，需白名单、沙箱和签名验证。

## 4. 能否解释 STA、AP、BSS、IBSS、DS、ESS、MPDU 和 MSDU 的含义及关系？

| 术语 | 含义 |
| --- | --- |
| **STA（基站）** | 符合 802.11 MAC 和物理层标准的设备 |
| **AP（接入点）** | 具有基站功能并通过无线介质提供分布式系统访问的实体 |
| **BSS（基本服务集）** | 由单个协调功能控制的一组基站，是 **WLAN 的最小组成单元** |
| **IBSS（独立 BSS）** | 没有 AP、基站彼此直接通信的自组网络 |
| **DS（分布式系统）** | 互连 BSS 并集成 LAN 的骨干系统 |
| **ESS（扩展服务集）** | 由 DS 互连的两个或多个 BSS，对 LLC 层表现为单个逻辑 LAN |
| **MPDU** | 对等 MAC 实体之间交换的数据单元（MAC 协议数据单元，帧） |
| **MSDU** | MAC 用户之间传输的信息单元（MAC 服务数据单元，上层数据） |

关系层次：MSDU 被封装进 MPDU；一个 BSS 含一个 AP 和若干 STA；多个 BSS 经 DS 互连构成 ESS；IBSS 是无 AP 的特殊 BSS。BSS 中 STA 通过 AP 转发帧，IBSS 中 STA 直接通信。

## 5. 能否说明 IEEE 802.11 物理层、MAC 层和 LLC 层分别承担什么功能？

| 层 | 功能 |
| --- | --- |
| **物理层** | 信号编码/译码、位传输/接收，定义传输介质、频带和天线特性 |
| **MAC 层** | 将上层数据封装为带地址和校验字段的 MPDU；接收时执行地址识别、错误检测（CRC/FCS）和介质访问控制（CSMA/CA） |
| **LLC 层** | 跟踪成功接收的帧并重发未成功的帧；MAC 主要负责检测错误和丢弃帧，重传由 LLC 负责 |

通用 MPDU 由 MAC 控制、目的 MAC 地址、源 MAC 地址、MSDU 和 CRC/FCS 组成。注意 CRC/FCS 只提供**检错**，不提供密码学完整性保护——攻击者可修改数据并重算 CRC。

## 6. 能否解释关联、重新关联、解除关联、分发和整合服务的作用？

802.11 定义九类服务，关键的五类：

| 服务 | 作用 |
| --- | --- |
| **关联（Association）** | STA 与 AP 建立映射关系，使 DS 知道该基站当前属于哪个 AP，之后帧才能经 DS 正确投递 |
| **重新关联（Reassociation）** | STA 从一个 BSS 漫游到同一 ESS 的另一个 BSS 时，与新 AP 重新建立关联，支持移动性 |
| **解除关联（Disassociation）** | 终止已有的关联关系，用于正常离开或 AP 强制断开 |
| **分发（Distribution）** | DS 中的核心服务，决定如何把帧从 AP 路由到目的 STA 所在的 AP |
| **整合（Integration）** | 连接 DS 与非 802.11 LAN（如有线以太网）时完成地址和介质的适配转换 |

关联服务使 DS 知道基站当前位置；认证、解除认证和隐私服务主要控制访问与安全。

## 7. 能否说明 WEP、WPA、WPA2、RSN 和 IEEE 802.11i 的演进关系？

| 标准/体系 | 定位 |
| --- | --- |
| **WEP** | 原始有线等效保密方案，其隐私和认证存在严重缺陷（RC4 密钥流重用、IV 过短、无真正密钥管理） |
| **WPA** | Wi-Fi 联盟在 802.11i 定稿前发布的过渡方案，采用 TKIP，可在旧 WEP 硬件上软件升级 |
| **IEEE 802.11i** | IEEE 制定的最终无线局域网安全标准，定义鲁棒安全网络（RSN）完整规范 |
| **RSN** | 802.11i 定义的**鲁棒安全网络**本身，提供认证、访问控制、隐私与完整性三类服务 |
| **WPA2** | Wi-Fi 联盟对符合完整 802.11i（RSN）产品的认证标识，强制支持 CCMP/AES |

演进线索：WEP（有缺陷）→ WPA（TKIP 过渡补丁）→ 802.11i/RSN（完整标准）→ WPA2（对完整标准的商业认证）。

## 8. 能否按发现、认证、密钥生成与分发、受保护数据传输、连接终止五阶段说明 RSN 操作？

| 阶段 | 操作 |
| --- | --- |
| **1. 发现** | AP 用 Beacon 和 Probe Response 公布安全策略；STA 识别 AP，协商密码套件（WEP/TKIP/CCMP）和认证密钥管理套件（802.1X/PSK），完成开放系统认证和关联 |
| **2. 认证** | STA 与认证服务器 AS 经 802.1X/EAP 相互证明身份；认证成功前 AP 阻塞普通数据流，只转发认证控制流 |
| **3. 密钥生成与分发** | STA 和 AP 通过四次握手生成并安装单播 PTK，通过组密钥握手分发组播 GTK |
| **4. 受保护数据传输** | 通过 AP 转发受 TKIP/CCMP 保护的数据帧；802.11i 主要保护 STA—AP 链路，不自动提供端到端安全 |
| **5. 连接终止** | 拆除安全连接，清除密钥，回到初始状态 |

这五阶段是新 STA 进入基础设施 BSS 时的强制性准入验证与安全通道建立流程。

## 9. 能否解释 IEEE 802.1X 中请求者、认证器、AS、不受控端口和受控端口的关系？

802.1X 是基于端口的网络访问控制标准，三个角色：

| 角色 | 对应实体 | 职责 |
| --- | --- | --- |
| **请求者（Supplicant）** | STA | 请求网络访问，响应认证请求 |
| **认证器（Authenticator）** | AP | 在请求者与 AS 之间转发认证消息，控制端口开闭 |
| **认证服务器（AS）** | 通常是 RADIUS 服务器 | 验证请求者凭证并作出授权决定 |

AP 的逻辑端口分为两类：

| 端口 | 状态 | 允许的流量 |
| --- | --- | --- |
| **不受控端口** | 认证前即开放 | 只允许 STA 与 AS 之间交换 EAP 认证 PDU |
| **受控端口** | 认证授权且四次握手安装密钥后才开放 | 允许普通数据流量 |

典型 EAP/RADIUS 流程：AP 请求 Identity → STA 响应（AP 经 RADIUS 封装发给 AS）→ AS 发 Challenge（可多轮）→ AS 返回 Access-Accept、AP 发 EAP Success，但受控端口要等四次握手安装密钥后才真正开放。

## 10. 能否区分 PSK/MSK、PMK、PTK、KCK、KEK、TK、GMK 和 GTK 的派生层次与用途？

**成对密钥层次（保护单播）**：

```text
PSK（预共享密钥）或 MSK/AAAK（认证阶段由 AS 生成）
  └─ PMK（成对主密钥）
       └─ PTK（成对临时密钥，由 PMK + 双方 MAC 地址 + 双 nonce 派生）
            ├─ EAPOL-KCK：保护四次握手控制帧完整性，证明持有 PMK
            ├─ EAPOL-KEK：加密 GTK 和握手中的其他密钥内容
            └─ TK：加密保护 STA 与 AP 之间的用户数据流
```

**组密钥层次（保护广播/组播）**：

```text
GMK（组主密钥）
  └─ GTK（组临时密钥，由 AP 分发给多播组内所有 STA）
```

| 密钥 | 用途 |
| --- | --- |
| **PSK/MSK** | 密钥层次顶层输入；PSK 直接作为 PMK，MSK 由认证过程生成 |
| **PMK** | 成对主密钥，派生 PTK 的根，不在握手消息中传输 |
| **PTK** | 成对临时密钥，每个 STA/AP 对独有，拆分为 KCK/KEK/TK |
| **KCK** | 密钥确认密钥，保护握手帧 MIC |
| **KEK** | 密钥加密密钥，加密分发的 GTK |
| **TK** | 临时会话密钥，实际加密用户数据 |
| **GMK/GTK** | 组主密钥/组临时密钥，保护一对多通信；设备离开网络时 GTK 必须更新 |

PMK/PSK、双方地址和时变值共同参与派生，保证每个 STA/AP 对拥有独特下层密钥。

## 11. 能否按四条消息描述 4 次握手，并说明 nonce、MAC 地址和 MIC 如何参与 PTK 生成与认证？

四次握手的目的：确认双方都持有 PMK、确认协商的密码套件、生成并安装新 PTK。

| 消息 | 方向 | 内容 |
| --- | --- | --- |
| **消息 1** | AP → STA | 发送 AP 的 MAC 地址和随机数 `Anonce` |
| **消息 2** | STA → AP | STA 生成 `Snonce`，用 PMK、双方 MAC 地址和两个 nonce 计算 PTK；发送自己的地址、`Snonce` 和由 **KCK 计算的 MIC** |
| **消息 3** | AP → STA | AP 用相同材料生成相同 PTK，验证消息 2 的 MIC 后，发送带 MIC 的密钥安装消息（可携带用 KEK 加密的 GTK） |
| **消息 4** | STA → AP | 发送受 MIC 保护的确认，双方安装密钥并开放受控端口 |

PTK 派生公式：

$$\mathrm{PTK} = \mathrm{PRF}\bigl(\mathrm{PMK}, \text{``Pairwise key expansion''}, \min(\mathrm{Addr}) \parallel \max(\mathrm{Addr}) \parallel \min(\mathrm{Nonce}) \parallel \max(\mathrm{Nonce}), 384\bigr)$$

- **双方 MAC 地址**：把密钥绑定到特定 STA/AP 对，防止会话转移；地址按字典序排列保证双方计算一致；
- **Anonce/Snonce**：双方各贡献一个随机数，保证每次连接 PTK 不同，提供新鲜性；
- **MIC**：用 PTK 中的 KCK 计算，证明发送方确实持有 PMK（从而能推出相同 PTK），同时保护握手消息完整性。

组密钥握手中，AP 用 KEK 加密 GTK 并附 MIC 发送，STA 解密安装后回送 MIC 确认。

## 12. 能否比较 TKIP 与 CCMP 的完整性、保密性和重放保护机制，并写出 IEEE 802.11i PRF 的输入和迭代结构？

| 方案 | 完整性 | 保密性 | 重放保护 |
| --- | --- | --- | --- |
| **TKIP** | Michael 算法根据地址、数据和密钥生成 64 位 MIC | RC4 加密 MPDU 和 MIC；256 位 TK 中部分材料用于 MIC，剩余形成 RC4 密钥 | 每帧递增 TSC（TKIP 序列号），TSC 受 MIC 保护并参与动态密钥生成 |
| **CCMP** | CBC-MAC 提供认证完整性 | AES-CTR 模式加密 | 48 位数据包号（PN）构造 CTR nonce，接收方拒绝序号倒退的帧 |

CCMP 使用 128 位 AES 同时支持保密性和完整性（CCM 认证加密），是新硬件的主要方案；TKIP 是为旧 WEP 硬件提供的软件升级过渡方案。

**IEEE 802.11i PRF** 形式为 $\mathrm{PRF}(K, A, B, \mathrm{Len})$：
- $K$：秘密密钥；
- $A$：用途标签（如 `Pairwise key expansion`）；
- $B$：地址、nonce 或时间等上下文；
- `Len`：所需输出位数。

迭代结构：

$$R = \varepsilon$$

$$R = R \parallel \mathrm{HMAC\text{-}SHA\text{-}1}(K, A \parallel 0 \parallel B \parallel i), \quad i = 0, 1, \ldots, \left\lceil\frac{\mathrm{Len}}{160}\right\rceil - 1$$

$$\mathrm{PRF}(K, A, B, \mathrm{Len}) = \operatorname{Truncate}_{\mathrm{Len}}(R)$$

同一框架还生成 nonce（标签 `Init Counter`，上下文为 MAC 地址和时间）和 GTK（标签 `Group key expansion`，上下文为 MAC 地址和 Gnonce）。
