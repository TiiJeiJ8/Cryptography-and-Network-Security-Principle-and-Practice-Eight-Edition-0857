# 第15章 密钥管理和分发

## 核心概念

密钥管理包括密钥生成、创建、保护、存储、交换、替换、使用、限制、监视和记录。密钥分发是在通信双方之间安全传递密钥的方法。

```mermaid
flowchart LR
    A["密钥生成"] --> B["注册/分发"]
    B --> C["存储与使用"]
    C --> D["更新/轮换"]
    D --> E["撤销/销毁"]
```

## 15.1 使用对称加密的对称密钥分发

### 15.1.1 四种基本方案

1. A 物理交付给 B；
2. 第三方物理交付给 A、B；
3. 用旧密钥加密新密钥；
4. A、B 与第三方各有加密连接，由第三方分发。

n 个实体两两共享密钥的数量：

$$
N_k=\frac{n(n-1)}2.
$$

物理交付不适合大规模端到端通信；用旧密钥递送新密钥会形成失陷链。

### 15.1.2 KTC 与 KDC

![[attachments/fig_15_1_pdf329.png]]

| 项目 | KTC | KDC |
| --- | --- | --- |
| 全称 | 密钥转换中心 | 密钥分发中心 |
| 会话密钥来源 | A 生成/取得 | KDC 生成 |
| 中心操作 | 从 $K_{ma}$ 下解密，再用 $K_{mb}$ 重加密 | 分别用 $K_{ma},K_{mb}$ 加密同一新密钥 |
| 最终目的 | A、B 得到 $K_s$ | A、B 得到 $K_s$ |

身份认证、时间戳、时变值和生命期是完整协议不可省略的部分。

### 15.1.3 密钥层次

![[attachments/fig_15_2_pdf330.png]]

| 密钥 | 生命期/频率 | 用途 |
| --- | --- | --- |
| 主密钥 | 长期、低频 | 包装和分发低层密钥 |
| 会话密钥 | 一次会话、较高频 | 加密业务数据 |
| 临时密钥 | 一次或极短 | 单次事务/中间操作 |

原则：高层密钥少用且强保护，低层密钥频繁轮换以缩小泄露范围。

## 15.2 使用非对称加密的对称密钥分发

### 15.2.1 简单方案与中间人攻击

![[attachments/fig_15_3_pdf331.png]]

$$
A\to B: PU_a\parallel ID_A,
$$

$$
B\to A:E(PU_a,K_s).
$$

弱点：$PU_a$ 未认证。

![[attachments/fig_15_4_pdf331.png]]

D 替换为 $PU_d$，解出 B 返回的 $K_s$，再用真实 $PU_a$ 重加密给 A。A、B 得到同一密钥，但 D 也知道它。

### 15.2.2 保密性与认证

![[attachments/fig_15_5_pdf332.png]]

挑战响应：

$$
A\to B:E(PU_b,ID_A\parallel N_1),
$$

$$
B\to A:E(PU_a,N_1\parallel N_2),
$$

$$
A\to B:E(PU_b,N_2).
$$

密钥传送：

$$
M=E(PU_b,E(PR_a,K_s)).
$$

B 恢复：

$$
D(PU_a,D(PR_b,M))=K_s.
$$

外层提供对 B 的保密，内层提供对 A 的来源绑定；前提是双方公钥真实。

## 15.3 公钥分发

### 15.3.1 公开发布

![[attachments/fig_15_6_pdf332.png]]

无需基础设施，但任何人可冒名发布公钥，无法认证身份-公钥绑定。

### 15.3.2 公开目录

![[attachments/fig_15_7_pdf333.png]]

目录项 `{名称, 公钥}`；注册和更新必须认证，访问应从管理员获得认证保护。集中风险：管理员私钥或目录记录失陷。

### 15.3.3 公钥授权

![[attachments/fig_15_8_pdf334.png]]

管理员签名应答包含：

- B 的当前公钥；
- A 的原始请求；
- 原始时间戳。

原始请求防应答错配，时间戳防旧公钥重放。缺点是管理员需在线应答并成为瓶颈。

### 15.3.4 公钥证书

证书要求：公开可读、CA 来源可验证、只有 CA 能创建/更新、时效可验证。

$$
C_A=E(PR_{auth},[T\parallel ID_A\parallel PU_a]).
$$

$$
D(PU_{auth},C_A)=T\parallel ID_A\parallel PU_a.
$$

![[attachments/fig_15_9_pdf335.png]]

证书可公开存放；真实性和完整性来自 CA 签名，不依赖目录保密。

## 15.4 X.509 证书

X.509 定义公钥证书格式与认证框架，不规定唯一签名算法或哈希函数。

![[attachments/fig_15_10_pdf336.png]]

### 15.4.1 证书

![[attachments/fig_15_11_pdf338.png]]

#### 字段

| 字段 | 核心含义 |
| --- | --- |
| 版本 | v1/v2/v3 |
| 序列号 | CA 内唯一 |
| 签名算法标识 | CA 签名算法与参数 |
| 发行商 | CA 名称 |
| 有效期 | notBefore/notAfter |
| 主体名 | 证书属主 |
| 主体公钥信息 | 公钥、算法和参数 |
| 唯一标识 | 发行商/主体名称复用时可选 |
| 扩展 | v3 扩展集合 |
| 签名 | 覆盖其他字段的 CA 签名 |

教材记法：

$$
CA<<A>>=CA\{V,SN,AI,CA,UCA,A,UA,A_p,T^A\}.
$$

#### 证书链

$$
X_1<<X_2>>\ X_2<<B>>,
$$

一般链：

$$
X_1<<X_2>>\ X_2<<X_3>>\cdots X_N<<B>>.
$$

![[attachments/fig_15_12_pdf338.png]]

- 前向证书：其他 CA 生成的 X 的证书；
- 后向证书：X 为其他 CA 生成的证书。

#### 证书撤销

提前撤销原因：

1. 主体私钥不安全；
2. 主体不再信任 CA、名称改变、证书废弃或错误签发；
3. CA 私钥不安全。

CRL 由发行商签名，含发行商、创建时间、下次发布时间，以及撤销证书的序列号和撤销时间。验证者要检查撤销状态，可缓存证书和 CRL。

### 15.4.2 X.509 v3 扩展

每个扩展有标识、critical 指示和值。实现不认识 `critical=TRUE` 的扩展时必须拒绝证书。

| 类别 | 扩展示例 |
| --- | --- |
| 密钥和策略 | 授权/主体密钥标识、密钥使用、私钥使用期、证书策略、策略映射 |
| 主体/发行商属性 | 主体可选名称、发行商可选名称、主体目录属性 |
| 路径约束 | 基本限制、名称限制、策略限制 |

## 15.5 公钥基础设施

PKI 是管理证书和公私钥对的策略、流程、服务器、软件和工作站集合。

![[attachments/fig_15_13_pdf341.png]]

| 组件 | 责任 |
| --- | --- |
| 终端实体 | 被证书认证的用户、设备、程序或服务 |
| CA | 创建/签名证书，发布 CRL，可生成主体密钥 |
| RA | 验证注册实体身份，分担 CA 管理 |
| 存储库 | 存储和提供证书、CRL |
| 信赖方 | 根据证书数据作安全决定 |

### 信赖方验证顺序

1. 可靠获得信任锚/CA 公钥；
2. 构建证书链；
3. 逐级验证签名；
4. 检查有效期和撤销；
5. 检查主体名称、密钥用途、路径/策略限制；
6. 才使用主体公钥。

## 易混淆对比

| 对比 | 区别 |
| --- | --- |
| KTC / KDC | KTC 转换实体产生的密钥；KDC 自己产生并分发 |
| 主密钥 / 会话密钥 | 前者长期包装密钥；后者短期保护业务 |
| 目录 / 证书 | 目录可信依赖在线管理员；证书本身带 CA 签名 |
| CA / RA | CA 签发并签名；RA 核验注册身份 |
| 过期 / 撤销 | 过期由有效期自动发生；撤销在未到期前提前失效 |
| 根 CA / 中间 CA | 根是本地信任锚；中间 CA 由上级证书授权 |

## 重点、难点与易错点

> [!IMPORTANT] 重点
> 密钥分发协议必须同时回答密钥保密、对方身份、密钥新鲜性和用途绑定四个问题。

> [!WARNING] 难点
> 公钥真实性、中间人攻击、证书链逐级验证、撤销与 v3 critical 扩展共同决定证书能否使用。

> [!CAUTION] 易错点
> - 加密的随机数可能被重放，不自动证明请求者身份。
> - “签名有效”不等于“证书对当前用途有效”。
> - 证书目录无需保密，但信任锚必须可靠获得。
> - CRL 中记录的是未到期但已撤销证书。

## 补充理解

> [!NOTE] 补充内容，非教材原文
> 工程中还常使用在线证书状态协议等机制检查撤销。无论采用何种状态服务，失败策略、缓存时效和网络不可用时的行为都属于安全设计，不能只验证证书签名字节。

## 关键词索引

- **CA**：证书颁发机构。
- **CRL**：证书撤销列表。
- **KDC**：生成并分发会话密钥的中心。
- **KTC**：把一个主密钥域中的会话密钥转换到另一个域的中心。
- **PKI**：公钥基础设施。
- **RA**：注册机构。
- **会话密钥**：保护一次逻辑连接的短期密钥。
- **密钥分发**：安全传递密钥的机制。
- **密钥管理**：覆盖密钥全生命期的过程和控制。
- **证书链**：从信任锚到主体证书的签发路径。
- **中间人攻击**：敌手替换密钥并分别维持两端通信。
- **主密钥**：长期保护低层密钥的高层密钥。
