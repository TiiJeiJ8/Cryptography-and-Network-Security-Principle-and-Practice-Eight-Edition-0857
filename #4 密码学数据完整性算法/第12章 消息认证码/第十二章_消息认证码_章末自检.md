# 第12章 消息认证码 — 章末学习目标自检

## 1. 能否列出八类通信攻击，并说明保密性、消息认证和数字签名各自主要抵抗哪些攻击？

网络通信环境中可能出现的八类攻击：

| 攻击 | 含义 |
| --- | --- |
| **泄露** | 消息被没有合适密钥的人或程序获得 |
| **通信量分析** | 敌手分析连接频率、持续时间、消息数量和长度等通信模式 |
| **伪装** | 欺诈源插入消息并声称来自合法实体，或发送关于收发的欺诈应答 |
| **内容修改** | 对消息内容进行插入、删除、换位或修改 |
| **序列修改** | 对消息序列进行插入、删除或重新排序 |
| **计时修改** | 对消息或会话进行延时和重放 |
| **发送方否认** | 发送方否认曾经发送过某条消息 |
| **接收方否认** | 接收方否认曾经收到过某条消息 |

三种安全机制的保护边界：

| 攻击范围 | 所需安全机制 |
| --- | --- |
| 泄露、通信量分析 | **消息保密性** |
| 伪装、内容修改、序列修改、计时修改 | **消息认证** |
| 发送方否认 | **数字签名** |
| 接收方否认 | **数字签名**与专门设计的协议 |

消息认证验证消息来源真实、内容未被篡改，还可验证顺序和及时性；数字签名在此基础上还能抵抗发送方否认。

## 2. 能否写出 $T=\operatorname{MAC}(K,M)$，并说明 MAC 可以证明什么、不能证明什么？

消息认证码（又称**密码校验和**）以共享密钥 $K$ 和可变长消息 $M$ 为输入，生成定长标记：

$$T = \operatorname{MAC}(K,M)$$

发送方发送 $M \parallel T$；接收方用同一密钥重新计算 MAC 并与收到的标记比较。在只有双方知道密钥且标记一致时，接收方可以确信：

1. **消息未被修改**——敌手不知道密钥，无法为篡改后的消息生成相符标记；
2. **消息来自真正的发送方**——其他参与者不能生成正确的 MAC；
3. **若消息含受 MAC 保护的序号，则顺序未被篡改**。

MAC **不能证明不可否认性**：因为发送方和接收方共享同一密钥，双方都能生成相同的 MAC，接收方无法向第三方证明消息确实来自发送方而非自己伪造——这是 MAC 与数字签名的根本区别。MAC 算法不要求可逆，是多对一函数，许多消息映射到同一标记。

仅发送 $M \parallel T$ 提供认证但不提供保密性；若同时需要保密，一般将 MAC 附在明文后再整体加密。

## 3. 能否解释安全 MAC 的三项基本要求，以及其穷举攻击强度为何是 $\min(2^k,2^n)$？

假设敌手知道 MAC 算法但不知道密钥 $K$，安全的 $n$ 位 MAC 应满足：

1. **抗伪造**：已知 $M$ 和 $\operatorname{MAC}(K,M)$，构造另一消息 $M' \neq M$ 使 $\operatorname{MAC}(K,M') = \operatorname{MAC}(K,M)$ 在计算上不可行；
2. **均匀分布**：对随机消息 $M$ 和 $M'$，标记相等的概率为 $2^{-n}$；
3. **抗已知变换**：若 $M' = f(M)$ 是对 $M$ 的已知变换（如某些位取反），仍应有 $\Pr[\operatorname{MAC}(K,M) = \operatorname{MAC}(K,M')] = 2^{-n}$，即消息任何部分都不应成为弱点。

**反例**：若 $\Delta(M) = X_1 \oplus X_2 \oplus \cdots \oplus X_m$，$\operatorname{MAC}(K,M) = E(K,\Delta(M))$，敌手可任意选择前 $m-1$ 个分组，再调整最后一个分组使异或和不变，从而在不知密钥的情况下沿用原标记完成伪造。

**穷举攻击强度**：
- 攻击密钥空间需约 $2^k$ 次操作（$k$ 为密钥长度）；
- 直接猜测 $n$ 位有效标记需约 $2^n$ 次操作。

敌手取两者中更容易的路径，因此总体强度为：

$$\min(2^k, 2^n)$$

若要求约 $N$ 位安全强度，应满足 $\min(k,n) \ge N$。当 $k > n$ 时，一个已知消息-MAC 对对应多个候选密钥，敌手需更多对筛选；但敌手不必恢复密钥，直接伪造标记的复杂度仍受 $2^n$ 限制。

## 4. 能否写出 HMAC 的完整公式，并解释 $K^+$、$\operatorname{ipad}$ 和 $\operatorname{opad}$ 的作用？

设嵌入哈希函数为 $H$（分组长度 $b$ 位，输出 $n$ 位），密钥为 $K$。若 $K$ 长于 $b$ 位先对其哈希，再用 0 填充到 $b$ 位得 $K^+$。$\operatorname{ipad}$ 为字节 `36` 重复 $b/8$ 次，$\operatorname{opad}$ 为字节 `5C` 重复 $b/8$ 次。HMAC 定义为：

$$\operatorname{HMAC}(K,M) = H\Bigl[(K^+ \oplus \operatorname{opad}) \parallel H\bigl((K^+ \oplus \operatorname{ipad}) \parallel M\bigr)\Bigr]$$

各要素作用：

| 要素 | 作用 |
| --- | --- |
| $K^+$ | 将密钥规范化为一个 $b$ 位分组，使其可与填充常量逐位异或 |
| $\operatorname{ipad}$（`36`） | 与 $K^+$ 异或形成**内层**密钥前缀，使内层哈希从一个秘密初始状态出发 |
| $\operatorname{opad}$（`5C`） | 与 $K^+$ 异或形成**外层**密钥前缀，与内层前缀不同，防止内外层状态相同 |

$K^+ \oplus \operatorname{ipad}$ 和 $K^+ \oplus \operatorname{opad}$ 相当于从同一密钥派生两个不同的伪随机前缀。对长消息，HMAC 与原哈希执行时间大致相同；若预计算两个前缀经压缩函数后的链接值，可加速短消息处理。

**安全性**：对 HMAC 的成功攻击等效于以下困难任务之一——(1) 在初始值随机、秘密且未知时计算压缩函数输出；(2) 在初始值随机且秘密时找哈希碰撞。普通哈希碰撞可离线搜索（默认 IV 公开），而 HMAC 的内部状态含密钥，敌手无法预计算，这是 HMAC 比直接哈希更适合认证的关键。

## 5. 能否说明定长 CBC-MAC 的弱点，以及 CMAC 如何用 $K_1$、$K_2$ 区分两类末分组？

**定长 CBC-MAC 的弱点**：数据认证算法（DAA）使用 DES-CBC（IV=0），最终输出 $O_N$ 作为认证码。它对**固定长度**消息安全，但不能安全扩展到任意长度。例如，已知单分组消息 $X$ 的 CBC-MAC 为 $T$，敌手可构造两分组消息 $X \parallel (X \oplus T)$，其 CBC-MAC 仍为 $T$，从而在不知密钥的情况下完成伪造。

**CMAC 的改进**：CMAC 从主密钥 $K$ 导出两个子密钥，明确区分两种消息结尾：

$$L = E(K, 0^b), \qquad K_1 = L \cdot x, \qquad K_2 = L \cdot x^2$$

乘法在 $\operatorname{GF}(2^b)$ 上进行（实现上即左移一位，溢出时与常数异或）。

对消息分组 $M_1, \ldots, M_n$：
- 若最后一组**恰为** $b$ 位（完整分组）：$M_n' = M_n \oplus K_1$；
- 若最后一组**不足** $b$ 位：右侧填充 `1` 和若干 `0`，再令 $M_n' = \operatorname{pad}(M_n) \oplus K_2$。

随后 CBC 链接：$C_0 = 0^b$，$C_i = E(K, M_i \oplus C_{i-1})$（$i < n$），$C_n = E(K, M_n' \oplus C_{n-1})$，标记 $T = \operatorname{MSB}_{T_{\text{len}}}(C_n)$。

关键不在于简单填充，而在于用 $K_1$、$K_2$ 使"完整末分组"和"填充末分组"两种情况在密码学上可区分，避免不同长度消息之间产生可利用的结构关系。

## 6. 能否区分 $H\rightarrow E$、$A\rightarrow E$、$E\rightarrow A$ 和 $E+A$ 四种认证加密组合方式？

认证加密（AE）同时提供保密性和完整性。四种通用组合方式：

| 方法 | 发送方处理 | 接收方顺序 | 教材示例 |
| --- | --- | --- | --- |
| **$H \rightarrow E$**（先哈希后加密） | 计算 $h = H(M)$，加密 $M \parallel h$ | 先解密，后验证 | WEP 类似方法 |
| **$A \rightarrow E$**（先认证后加密） | 计算 $T = \operatorname{MAC}(K_1, M)$，加密 $M \parallel T$ | 先解密，后验证 | SSL/TLS |
| **$E \rightarrow A$**（先加密后认证） | 先得 $C = E(K_2, M)$，再计算 $T = \operatorname{MAC}(K_1, C)$ | **先验证，后解密** | IPsec |
| **$E + A$**（独立加密和认证） | 分别计算 $C = E(K_2, M)$ 与 $T = \operatorname{MAC}(K_1, M)$ | 先解密，后验证 | SSH |

后三种通常使用两个独立密钥（加密密钥和认证密钥）。组合方式本身不自动保证安全——参数、格式和验证顺序都必须正确设计。$E \rightarrow A$ 的优势是接收方在验证通过前不解密，可阻止某些针对解密器的选择密文攻击。CCM 和 GCM 是 NIST 标准化的专用认证加密模式。

## 7. 能否说明 CCM 的三个输入，并概括 CMAC 认证和 CTR 加密的处理流程？

CCM 由 AES + CTR 模式（加密）+ CMAC（认证）组成，加密与 MAC 共用密钥 $K$。三个输入：

| 输入 | 含义 |
| --- | --- |
| **明文 $P$** | 既要认证又要加密的数据 |
| **关联数据 $A$** | 只认证、不加密的数据（如必须明文传输的协议首部） |
| **时变值 $N$** | 在协议寿命期内每个实例取不同值，用于阻止重放攻击 |

**认证阶段**：将 $(N, A, P)$ 格式化为分组 $B_0, B_1, \ldots, B_r$，执行类 CBC-MAC 链接：

$$Y_0 = E(K, B_0), \qquad Y_i = E(K, B_i \oplus Y_{i-1})$$

$$T = \operatorname{MSB}_{T_{\text{len}}}(Y_r)$$

**加密阶段**：生成计数器分组 $\operatorname{Ctr}_0, \operatorname{Ctr}_1, \ldots$。$\operatorname{Ctr}_1$ 以后的输出用于 CTR 加密明文，$\operatorname{Ctr}_0$ 的输出用于掩蔽认证标记：

$$C_P = P \oplus \operatorname{MSB}_{P_{\text{len}}}(S_1 \parallel S_2 \parallel \cdots)$$

$$C_T = T \oplus \operatorname{MSB}_{T_{\text{len}}}(S_0)$$

最终输出 $C = C_P \parallel C_T$。接收方先用 CTR 恢复明文和标记，再由 $(N, A, P)$ 重新计算 CMAC 验证。CCM 对明文需两次完整处理（一次算 MAC、一次加密），结构较复杂但安全性高。

## 8. 能否说明 GCM 中 GHASH、GCTR、$H$ 和 $J_0$ 的作用，并写出密文与标记的核心公式？

GCM 以 CTR 模式加密，在 $\operatorname{GF}(2^{128})$ 上计算认证值，设计可并行，适合高吞吐量场景。只认证不加密的变体称 GMAC。

| 组件 | 作用 |
| --- | --- |
| **$H$** | 哈希密钥，$H = E(K, 0^{128})$，由主密钥加密全零分组得到，用于 GHASH |
| **GHASH** | 带密钥的认证函数：$Y_i = (Y_{i-1} \oplus X_i) \cdot H$，乘法在 $\operatorname{GF}(2^{128})$ 上；等价于 $X_1 H^m \oplus X_2 H^{m-1} \oplus \cdots \oplus X_m H$，可并行 |
| **GCTR** | 计数器递增的 CTR 模式，对计数器分组加密后与输入异或，可并行 |
| **$J_0$** | 预计数器分组；96 位 IV 时 $J_0 = IV \parallel 0^{31} \parallel 1$，其他长度经 GHASH 生成 |

**核心流程**：

$$C = \operatorname{GCTR}_K(\operatorname{inc}_{32}(J_0), P)$$

将关联数据 $A$、密文 $C$、填充及二者长度字段连接后 GHASH：

$$S = \operatorname{GHASH}_H\bigl(A \parallel 0^v \parallel C \parallel 0^u \parallel [\operatorname{len}(A)]_{64} \parallel [\operatorname{len}(C)]_{64}\bigr)$$

$$T = \operatorname{MSB}_t\bigl(\operatorname{GCTR}_K(J_0, S)\bigr)$$

关联数据 $A$ 虽不加密，但被纳入 GHASH 计算，其完整性同样受保护。GCM 效率来自 CTR 加密可并行、GHASH 仅使用易于硬件实现的 Galois 域乘法。

## 9. 能否解释密钥封装为何需要固定 ICV，以及封装输出为何比输入多一个 64 位分组？

密钥封装（KW）使用双方预共享的**密钥加密密钥（KEK）**安全交换新的对称密钥。待封装密钥可能长于分组长度（如 AES-128 分组而密钥为 192/256 位），且密钥泄露影响远大于普通数据，因此封装模式要求输出各位以复杂方式依赖全部输入位。

**固定 ICV 的作用**：封装时初始化完整性校验值：

$$A(0) = \texttt{A6A6A6A6A6A6A6A6}$$

将明文密钥分为 $n$ 个 64 位分组 $R(0,i) = P_i$，执行 $s = 6n$ 个阶段。每阶段：

$$W = E\bigl(K, A(t-1) \parallel R(t-1,1)\bigr)$$

$$A(t) = \operatorname{MSB}_{64}(W) \oplus [t]_{64}, \qquad R(t,n) = \operatorname{LSB}_{64}(W)$$

其余 $R$ 寄存器前移。解封时按阶段逆序解密，恢复 $A(0)$。若恢复的 $A(0)$ 不等于固定值 `A6A6A6A6A6A6A6A6`，说明密文被篡改或损坏，必须拒绝。因此 ICV 提供了**完整性验证**——密钥封装同时保护保密性和完整性。

**输出多一个 64 位分组**：输出为 $(C_0, C_1, \ldots, C_n) = (A(s), R(s,1), \ldots, R(s,n))$，其中 $C_0 = A(s)$ 占用一个额外 64 位分组来携带 ICV 信息。多阶段反馈和寄存器移动增强了雪崩效应与混淆。

## 10. 能否比较基于哈希函数和基于 HMAC 的 PRNG 在状态更新、性能与安全性方面的差异？

PRNG 由秘密种子和确定性算法组成。分组密码、哈希函数和 HMAC 的输出都具有伪随机性质，均可作为 PRNG 基础。

| 对比项 | 基于哈希函数的 PRNG | 基于 HMAC 的 PRNG |
| --- | --- | --- |
| **状态更新** | $w_i = H(V)$，$V = (V+1) \bmod 2^{\text{seedlen}}$，种子递增 | $w_i = \operatorname{HMAC}(K, w_{i-1})$，前一输出作为下一次输入；密钥 $K$ 不变，周期性更新 $K$、$V$ |
| **种子要求** | $\text{seedlen} \ge K + 64$（$K$ 为所需安全强度） | 输入为密钥 $K$ 和种子 $V$ |
| **性能** | 每个输出分组只需一次哈希运算，较快 | 每个输出分组通常需两次哈希运算，较慢 |
| **安全性** | 对 SHA-2 等强哈希无已知缺陷 | 更令人放心，可提供更高安全性；即使敌手观察到链式输入输出，只要 HMAC 安全就不能恢复 $K$ 或预测后续位 |

教材还比较了三种 HMAC 构造：NIST SP 800-90（前一输出作下一输入）、IEEE 802.11i（种子与递增计数器连接）、TLS/WTLS（先算中间链 $A(i)$，再对 $A(i) \parallel V$ 调用 HMAC）。两者均需周期性更新内部状态以防回溯。
